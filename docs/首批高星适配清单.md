## 1. 方法、口径与证据分级

### 1.1 流程（按证据成本从低到高）

1. **复算候选面**：初始候选集里的 20 个仓库名 → 用 1 次 GitHub API `GET /search/repositories?q=dsh&sort=stars&per_page=100` 解析 `full_name`；未命中的 2 个（oh-story-dsh、dsh-plugin-shop）各用 1 次 `q=<name> in:name` 补齐；MemOS/EverOS/plugin-radar/dsh-plugins/dsh-mobile 用 `GET /repos/{owner}/{repo}` 取 `default_branch/archived/pushed_at/description`。【事实】
2. **是不是真插件**：优先 `raw.githubusercontent.com/<owner>/<repo>/<main|master>/package.json`（不耗 API 配额）——只看 `dsh.client` / `dsh.bundle.patch` / `dsh.manifestVersion` / `exports['./client']`。【事实】
3. **移动端有没有可适配面**：拉客户端 bundle（`dsh.client` 指向的入口，或 package.json `exports['./client']`），grep 四类信号：①slot 注册（`slots.inject('…')`）②DOM 标记（`data-*` / role / aria）③移动端风险（固定 px 宽、`min-width`、`100vh`、宽表格、`white-space:nowrap`、`position:absolute|fixed`、`:hover`）④面板入口与挂载容器。【事实】
4. **可验证性分档**：对照 `check-pack` 的静态规则（v0.3.1 `42a61ee`：`static.css.third-party` :332、`thirdPartyMarkers` :726、`static.css.scope` :337、`selectorScope` :706）与定向 fixture 机制（`inspectFixture` :427、内置 `FIXTURE` :749）判定，不看插件自我描述。【事实】

### 1.2 可验证性三档定义（本轮新增列）

| 档 | 判定标准 | 能做什么 |
|---|---|---|
| **A** | 面板根/关键控件带 **`data-dsh*` 自有契约标记**（或 `[data-slot]`/`[role]` 可直接命中），可合成一个 panel 级 fixture 快照 → 定向 fixture 后断言能真实命中 | 可做"引用具体插件"的 pack（**定向 fixture 已支持**，见 [定向-fixture.md](./定向-fixture.md)；忠实度审查见收录标准 §8.1） |
| **B** | 只有 CSS Module 哈希（`pI_x6G_*`/`nUhMVa_*` 这类）、或自有稳定类名（`.lc-*`/`.dshp-*`/`.ofm_*`）、或 `data-<plugin>-*`（非 `data-dsh*`）——**pack 静态层禁止使用**（v0.3.1 `static.css.third-party` :332 / `thirdPartyMarkers` :726，只允许 `.dshm-*`/`[data-slot]`/`[role]`/`data-dsh*`） | 建议**向上游提 PR**：加 `data-dsh-*` 面板标记 + 窄容器/44px 适配；pack 等上游合并后再做 |
| **C** | canvas/WebGL 自绘、原生窗口/App 集成、无客户端 UI（纯服务端/provider/目录数据仓库）、或 UI 不在 main/sidebar/settings 任一入口 | 明确不建议 |

> 关键事实：B 档不是"插件差"，而是**pack 的选择器契约无法合法点名它**；[收录标准.md](./收录标准.md) §3 补充规则已明确"不依赖 CSS Module 哈希（`pI_x6G_` 这类前缀每次构建都会变），只用 data-slot / [role=dialog] / 已登记的 .dshm-* / 包自己写的标记"。

### 1.3 证据分级约定

- 【事实】给 `文件:行`（仓库源码/构建产物/本机 profile）或命令输出；
- 【推断】是从代码结构推出但未渲染验证的行为；
- 【需实测】交给后续 pack 实现/真机验证阶段，本文不预设结论。

### 5.2 逐条排除理由（简）

1. `dsh-desktop` / `DSH-X`：桌面端，移动端无 UI 面，且本仓不改编原生壳（收录标准 §1「不收外壳级适配」）。
2. `awesome-dsh-plugin` / `dsh-plugin-radar` / `dsh-plugin-shop` / `dsh-plugins`：聚合/目录/合集，不是可注入 UI 的插件，`target` 无处可指（收录标准 §5.2 规则 5 要求点名某插件）。
3. `dsh-web`：全家桶 bundle，无自身 client；若未来其内置子插件有 UI，应点名子插件而不是这个聚合包。
4. `dsh-TUI`：终端界面，不经过浏览器 DOM，无移动 web 面。
5. `ds-harness-remote`：远程访问客户端，与 dsh-mobile 的移动接入目标冲突；同装会形成两套远程通道。
