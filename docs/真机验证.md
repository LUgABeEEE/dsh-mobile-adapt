# 真机验证：Android App 上的专用移动页

> 状态：**第一轮真机验证，已完成（2026-11-01）**。
> 设备：Redmi K90 Max（2604FRK1EC）· Android 17（SDK 37）· dsh-mobile Android App 0.7.1。
> 宿主：dsh-mobile 0.8.0 网关 + DSH 0.2.1-rc.3（隔离 `DSH_HOME`）。
> 这份文档回答：**适配包在真实手机 App 的专用页上是否成立、测量口径是什么、哪些结论仍然不能由真机给出。**

## 1. 结论

| 问题 | 结论 |
| --- | --- |
| 适配包在真机 App 上生效吗？ | **是**。无包时主槽 141 个控件全部 <44px（最小 14px）；装 `core-panel` 或两个包后 **141→0 个 <44**（最小 44px）。 |
| `dshmarket-mobile` 只作用于市场根吗？ | **是**。只装它时市场根 138 个控件 44/0，主槽其余控件仍 20/3（未越界）。 |
| 真机的 `env(safe-area-inset-*)` 有值吗？ | **本 App 版本为全 0**：WebView 内缩在系统栏之内（非 edge-to-edge，`screen 853 - inner 786 = 67 CSS px`），inset 由 Android 原生布局消化，CSS 读不到。 |
| 软键盘会改变视口吗？ | **会**。App 内 `innerHeight 786 → 472`（键盘占 **314 CSS px**），layout viewport 直接收缩（adjustResize）。 |
| 和桌面无头专用页一致吗？ | **逐项一致**（before/after 数字相同）；差异见 §5.4。 |

## 3. 怎么把 App 连到隔离实例

这台手机所在的 Wi-Fi 有 **AP 隔离**：手机（`10.71.24.118/16`）ping 不通、也连不上 PC（`10.71.236.97`）的任何端口，`nc` 到网关 `:3443` 直接超时。因此没有走"同一 Wi-Fi 直连"，而是用 USB：

```text
手机 127.0.0.1:3443  --adb reverse-->  PC 127.0.0.1:3443
  --TLS 终止代理（证书由 dsh-mobile CA 签发，SAN=127.0.0.1；Host/Origin 改写为 10.71.236.97:3443）-->
  PC 网关 https://10.71.236.97:3443
```

- `adb reverse tcp:3443 tcp:3443` 把手机的 loopback 端口接到 PC；
- PC 侧代理监听 `127.0.0.1:3443`，终止 TLS 后以正确 Host/Origin 转发到网关（WebSocket upgrade 同样透传）；
- 配对二维码指向 `https://127.0.0.1:3443/mobile-access/pair#instance=…&token=…`，App 扫码即配对；
- 配对窗口默认只活 **120s**，验证时用一个自动刷新的二维码页（每 ~90s 重新 `POST /api/mobile-access/pairing/open`）。

> 这是**测试装置**，不是产品能力：普通用户在无 AP 隔离的局域网里直接扫码即可，不需要 adb reverse 和代理。

配对成功：`GET /api/mobile-access/devices` 出现 `DeepSeek Harness Android`，App 进入全屏 WebView 专用页。

## 4. 怎么在 App 里测量

App 的 WebView **没有开调试**（`/proc/net/unix` 无 devtools socket），所以无法 CDP。改用 dsh-mobile 自带的自定义脚本通道：

1. 在隔离 `DSH_HOME` 写 `mobile-access/mobile.js`（网关会加载/热更新）；
2. 脚本注入一个只读浮层，显示 `env(safe-area-inset-*)`、`innerWidth/Height`、`visualViewport`、DPR，以及按 `docs/收录标准.md` §3 口径统计的 slot / market 控件数（`button` / `[role="button"]` / `select` / `input`(非 checkbox/radio) / `textarea`，可见元素，`min(width,height)`）；
3. `adb shell screencap` 截图读取数值（浮层固定顶部，绿色等宽字体）。

脚本只存在于隔离实例，**不随仓库发布**；测量口径与 `check-pack` 一致，因此数字可以和桌面结果直接对比。

## 5. 结果

### 5.1 视口与 safe-area（App 全屏 WebView，专用页）

```
sa=0,0,0,0   dpr=3.25   screen=394x853
inner=394x786   vv=394x786   dk=0
dshm=true
```

- `env(safe-area-inset-*)` **全 0**：App 把 WebView 放在系统栏内，67 CSS px（状态栏 ~47 + 导航栏 ~20）由原生布局消化；因此当前版本不需要 CSS safe-area 适配。
- 若 App 将来改成 edge-to-edge（`viewport-fit=cover`），这里才会变成非 0，需要重新测——不能把本次的 0 当作"永久结论"。

### 5.2 软键盘

| 状态 | `innerHeight` | 说明 |
| --- | --- | --- |
| 键盘关闭 | **786** | 基线 |
| 键盘弹出 | **472** | 键盘占 **314 CSS px** |
| 差值 | **314** | layout viewport 收缩（adjustResize），不是只缩 `visualViewport` |

输入框在键盘上方保持可见，页面未出现横向溢出。

### 5.3 适配包 before/after 对照（真机 App，同一路径）

路径：App → 侧边栏 → 插件 → 插件市场；只改变 `extensions/` 里的包：

| 状态 | slot（n / 最小边 / <44） | market 根（n / 最小边 / <44） |
| --- | --- | --- |
| 无包（before） | 141 / **14px** / **141** | 138 / **14px** / **138** |
| 只装 `core-panel` | 141 / **44px** / **0** | 138 / **44px** / **0** |
| 只装 `dshmarket-mobile` | 140 / 20 / 3 | 137 / **44px** / **0** |
| 两个都装（after） | 141 / **44px** / **0** | 138 / **44px** / **0** |

截图：`before-none.png`（before）、`after-both.png`（after）、`keyboard-open.png`（键盘）。

### 5.4 与桌面无头专用页对照（390×844）

| 状态 | 桌面 slot | 真机 slot | 桌面 market | 真机 market |
| --- | --- | --- | --- | --- |
| 无包 | 141 / 12.1 / 141 | 141 / **14** / 141 | 138 / 12.1 / 138 | 138 / **14** / 138 |
| `core-panel` | 141 / 44 / 0 | 141 / 44 / 0 | 138 / 44 / 0 | 138 / 44 / 0 |
| `dshmarket-mobile` | 141 / 20 / 3 | **140** / 20 / 3 | 138 / 44 / 0 | **137** / 44 / 0 |
| 两个都装 | 141 / 44 / 0 | 141 / 44 / 0 | 138 / 44 / 0 | 138 / 44 / 0 |

差异解释（都不是包的问题）：

- **无包基线 14px vs 12.1px**：真机字体栈与 Chromium 无头渲染不同，最小边是 CSS px 的实际计算结果，允许有差异；
- **`dshmarket-mobile` 单独时 n 少 1**（140/137 vs 141/138）：市场列表是虚拟滚动，渲染数量随视口高度变化（真机 inner 786 vs 桌面 844）；
- **连续快速重启 App + 反复加载**会触发 App 的"远程服务限流"（`{"error":"busy"}`，因为经 loopback 代理的连接被归为远程）；正常使用不会触发。

## 6. 边界 / 未验证

1. **单机单系统**：只测了 Redmi K90 Max / Android 17 / App 0.7.1；其他厂商 WebView、iOS、平板/折叠屏未测。
2. **iOS 完全未覆盖**：没有设备；iOS Safari / WKWebView 的 safe-area、软键盘、渲染差异仍需单独验证。
3. **拇指手感未测**：本轮的"命中区"是 CSS 尺寸（`getBoundingClientRect` 的 `min(width,height)`），不是手指真实触达；用伪元素扩边等"隐形命中区"仍需 `elementFromPoint` 边缘探测（已在浏览器面验证过方法）。
4. **App 非 edge-to-edge**：safe-area=0 是当前 App 布局的结果，不能推广到未来 edge-to-edge 版本。
5. **测试装置不通用**：adb reverse + TLS 代理是为了绕开 AP 隔离的临时方案；正常局域网无需。
6. **数据是快照**：在线市场列表会变（本轮 138/137 个控件），复测请同时记录日期与版本。

## 7. 复现步骤

```powershell
# 1) 手机开 USB 调试；PC 侧 adb
adb devices -l
adb reverse tcp:3443 tcp:3443

# 2) PC 侧：隔离实例起网关（dsh-mobile 0.8.0，LAN 地址按本机网卡选择）
#    并在 127.0.0.1:3443 起 TLS 代理（证书由 dsh-mobile CA 签发，SAN=127.0.0.1）
#    二维码内容：https://127.0.0.1:3443/mobile-access/pair#instance=<id>&token=<token>

# 3) App：局域网访问 → 扫码 → 连接；确认设备出现在
curl http://127.0.0.1:<admin-port>/api/mobile-access/devices

# 4) 测量：在隔离 DSH_HOME 的 mobile-access/mobile.js 注入浮层，然后
adb shell am force-stop io.github.sayach.dshmobile
adb shell am start -W -n io.github.sayach.dshmobile/.MainActivity
adb shell screencap -p /sdcard/probe.png && adb pull /sdcard/probe.png .
```

`docs/phone-instance.md` 描述的是 headless 驱动专用页（桌面浏览器口径）；真机（App）口径以本文为准。
