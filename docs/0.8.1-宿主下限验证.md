# dsh-mobile 0.8.1 宿主下限验证（发布版 #319）

> 2026-11-01 · 验证对象：**dsh-mobile 0.8.1**（npm `latest`，2026-11-01 发布，包含 #319）
> 宿主：隔离 `DSH_HOME` + 真实网关 `https://<lan-ip>:3443`，headless Chromium 390×844 粗指针。
> 这份文档回答两个此前标注为「未实测」的问题：
> 1. 发布版里宿主自己给插件面板的 44px 下限是否真的生效；
> 2. 装了 `core-panel` / `dshmarket-mobile` 之后，0.8.1 上会发生什么（叠加、冲突，还是退让）。

## 1. 结论

| 状态（0.8.1 网关，桌面 headless 专用页） | 主槽控件（n / 最小边 / <44） | 市场根（n / 最小边 / <44） | 包样式 |
| --- | --- | --- | --- |
| **无包（宿主自带）** | 141 / **44px** / **0** | 138 / **44px** / **0** | — |
| 只装 `core-panel` | 141 / 44 / 0 | 138 / 44 / 0 | `core-panel` |
| 只装 `dshmarket-mobile` | 141 / 44 / 0 | 138 / 44 / 0 | `dshmarket-mobile` |
| 两个都装 | 141 / 44 / 0 | 138 / 44 / 0 | 两者 |
| **无包** + 文档级 `data-dsh-adapt="off"` | 141 / **12.1** / **141** | 138 / **12.1** / **138** | —（宿主下限被 opt-out 关闭） |

对比 **0.8.0**（同一测量口径，`work/dedicated-page-verify` 的既有数据）：

| 状态 | 0.8.0 主槽 | 0.8.0 市场根 | 0.8.1 主槽 | 0.8.1 市场根 |
| --- | --- | --- | --- | --- |
| 无包 | 141 / 12.1 / 141 | 138 / 12.1 / 138 | **141 / 44 / 0** | **138 / 44 / 0** |
| 两个包都装 | 141 / 44 / 0 | 138 / 44 / 0 | 141 / 44 / 0 | 138 / 44 / 0 |

**结论：**
1. **0.8.1 的宿主下限确实生效**：不装任何包，面板内全部控件（141 个主槽 / 138 个市场根）最小边已经是 44px，`<44` 为 0；`data-dsh-panel="1"` 由宿主写入。
2. **两个适配包在 0.8.1 上对这个市场面板是 no-op（不叠加、不冲突）**：`core-panel` 的 `data-dsh-panel` 门阀按预期退让，`dshmarket-mobile` 的规则与宿主下限同值；测量结果与无包完全一致。**边界**：宿主下限的 selector **不含 `textarea`**（见 §3），所以这个结论只覆盖无 textarea 的插件市场面板（本轮面板 inputs=1，没有 textarea）；两个包里的 textarea 规则在 0.8.1 上仍可能起作用，本面板未测到差异。
3. **文档级 opt-out 会同时关掉宿主下限**：把 `data-dsh-adapt="off"` 设在 `<html>` 上后，宿主下限也消失（回到 12.1/141 与 138/138）——这不是包的行为，而是宿主 CSS 的 `[data-dsh-adapt="off"] *` 排除规则（见 §3）。面板级 opt-out（只设在目标插件根）是否影响宿主下限，本轮未单独测。

## 2. 方法（可复跑）

```bash
# 1) 隔离实例：DSH 0.2.1-rc.3 + profiles/web（dsh-mobile 由 npm tarball 提供）
#    目标是 0.8.1：把 profiles/web/node_modules/dsh-mobile 换成 npm pack 出来的 0.8.1
# 2) 起网关（LAN 3443），用 dsh-ui-lab 的 mobile surface 配对一次
node <dsh-ui-lab>/src/cli.mjs shot --surface mobile --profile phone-390x844 \
  --url https://<lan-ip>:3443 --fresh --out evidence/pairing --json
# 3) 同一路径（抽屉 → 插件 → 插件市场）逐状态测量；口径与 check-pack 一致
node measure.mjs --state .cache/mobile-state.json --url https://<lan-ip>:3443 \
  --out evidence/<state> --tag <state>
```

- 计数口径：可见 `button` / `[role="button"]` / `select` / `input`(非 checkbox/radio) / `textarea`，`min(width,height)`，`<44` 计数（与 `check-pack` 相同）；
- 每个状态都重新打开面板、重新量；扩展状态通过移动 `extensions/` 目录切换，切换后等 4 秒让网关重载；
- opt-out 用 `--optout`（`document-start` 在 `<html>` 上设 `data-dsh-adapt="off"`）。

## 3. 机制（为什么 0.8.1 会自带下限）

0.8.1 的 `lib/mobile-layout.js` 新增了四条规则（完整选择器见文件 505–508 行）：

```css
/* 面板内容滚动与宽度收口 */
.dshm-main[data-dsh-panel="1"] .dshm-mainContent:has(>[data-slot="main"]>:not([data-dsh-adapt="off"]))... { overflow-y:auto; overscroll-behavior:contain }
.dshm-main[data-dsh-panel="1"] .dshm-mainContent>[data-slot="main"]>:not([data-dsh-adapt="off"]) { max-width:100%; box-sizing:border-box }

/* 触控下限：主槽内插件面板的 button / [role="button"] / select / input（不含 textarea） */
.dshm-main[data-dsh-panel="1"] [data-slot="main"]>:not([data-dsh-adapt="off"])
  :is(button,[role="button"],select,input:not(...)):not([role="switch"],[role="checkbox"],[role="radio"],[role="slider"],[data-dsh-adapt="off"],[data-dsh-adapt="off"] *)
{ min-width:44px !important; min-height:44px !important }
```

- 规则范围（逐条）：

- 505–506：面板内容滚动容器与面板根 `max-width:100%` 收口；
- 507：控件下限 **44×44**（`button` / `[role="button"]` / `select` / `input`，排除 checkbox/radio/range/hidden/color/file/image 与 switch/checkbox/radio/slider 角色），**不包含 `textarea`**；
- 508：`button` / `[role="button"]` / `a` 的 `touch-action:manipulation`。

`data-dsh-panel` 由宿主 `mobile-layout.js` 写入（active panel 时 `"1"`），这也是 `core-panel` 门阀（`.dshm-main:not([data-dsh-panel])`）退让的依据；
- 宿主下限沿用生态既有的 opt-out 约定 `data-dsh-adapt="off"`；`[data-dsh-adapt="off"] *` 会排除**所有后代**，因此把属性设在 `<html>` 上会整体关闭下限（实测：12.1/141）。这意味着 opt-out 在 0.8.1+ 上的语义是「连宿主下限一起关」，不只是关适配包。

## 4. 对仓库的影响

- `README.md` 的「Real runtime on main after #319：❌ 没有发布版包含」已经过时：**0.8.1 就是包含 #319 的发布版**，且已实测。
- `core-panel` 的 `catalog.json` 里「含 #319 的发布版（≥0.8.1，尚无 tag）上的真实运行时」这一缺失项可以关闭：0.8.1 上宿主下限生效、本包在该市场面板上退让为 no-op（上面的数据）。
- `dshmarket-mobile`：在 0.8.1+ 的实测市场面板（无 textarea）上同样 no-op；本包仍然是为 **0.8.0 及更早** 的宿主提供下限，并保留宿主下限不覆盖的 textarea/touch-action 规则。是否在 0.8.1+ 上继续安装由用户决定（无害；只有 textarea 场景可能仍有差异，未实测）。
- 两个包升 `candidate` 仍缺：iOS/其他 Android WebView、拇指真实触达、edge-to-edge 场景（真机轮次见 `docs/真机验证.md`，该轮用的是 0.8.0 网关）。

## 5. 边界 / 未验证

1. 只在 **桌面 headless Chromium 390×844** 上测；0.8.1 的真机 App 复测未做（测量当天手机 USB 断连，未重跑）。
2. 只测「插件 → 插件市场」这一个面板状态（该面板没有 `textarea`）；含 textarea 的面板状态未覆盖，因此「no-op」不能外推到所有面板。
3. 面板级 opt-out（目标插件根 `data-dsh-adapt="off"`）对宿主下限的影响未单独测；本文只测了文档级。
4. DSH 为 0.2.1-rc.3；0.8.1 官方声明支持到 0.2.2-alpha.2，其他 DSH 版本未测。
5. 在线市场列表内容会变（本轮 138/141 个控件），复测请记录日期与版本。
