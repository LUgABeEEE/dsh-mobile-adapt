# 收录标准

**状态**：草案（2026-10-30）· 目标基线 dsh-mobile **0.8.0** + DSH **0.2.1-rc.2**（实测在 0.7.1 上做过）
**适用**：`packs/<id>/` 下的适配包收录、审查、验证。运行时是 dsh-mobile 的 `$DSH_HOME/mobile-access/extensions/`，本仓库不改宿主产物。

数字口径来源（直接引用，不重造）：dsh-mobile `docs/MOBILE_PLUGIN_ADAPTATION.md`、`design-system/MASTER.md`、WCAG 2.2 SC 2.5.5（44×44，AAA）；我们那份 L1/L2/L3 基线在 PR #316，**仍是提案**。本文档是这些口径的「可执行版」。

---

## 1. 收什么，不收什么

**收**：第三方插件**自己的面板**在移动端的适配——面板容器宽度/让位、按钮与输入的触控目标、面板状态区的滚动、`data-dsh-chrome` 语义契约的折叠。

**不收**：

- 外壳级适配（抽屉、设置页、输入栏、主题、PWA）——dsh-mobile 专用页已经做了，且社区 15+ 个仓库在这块互相打架；
- 重实现宿主已有能力（例如自己再写一套侧栏抽屉）；
- 通配兜底层（「所有插件面板按钮一律 44px」且无点名、无 opt-out、不可单独关闭的组合）；
- 改已安装 DSH 产物、改 `lib/`、往 `$DSH_HOME` 根上写 `mobile.css` 的做法（那是另一条 hotfix 通道，不进收录表）。

**定位**：本仓库是上游之前的家。上游收编某项适配后，对应包转 `status: retired`，不再同步。

## 2. 包的硬约束（CI 静态层）

| 约束 | 规则 | 失败即拒 |
|---|---|---|
| 字段 | `extension.json` **只能 5 个**：`schemaVersion`（必须 `1`）、`id`、`name`、`version`、`description` | 多一个字段整包被运行时拒绝 |
| id | 必须等于目录名，匹配 `^[a-z][a-z0-9-]{0,63}$` | 是 |
| 文件 | 只允许 `extension.json` / `mobile.css` / `mobile.js` / `host.mjs` / `assets/` / `README.md` / `shots/`；运行时可执行面只有前三类 | 是 |
| 体积 | `mobile.js` ≤ 1 MB、`mobile.css` ≤ 512 KB、`extension.json` ≤ 64 KB、`assets/` 单文件 ≤ 8 MB 且 ≤ 256 个 | 是 |
| 元信息位置 | status / risk / default / target / capabilities / surfaces / usesHostMarkers / verifiedWith 只能在根 `catalog.json` | 是 |
| 模板 | `packs/_template` 以下划线开头，**不参与校验**（`check-pack` 跳过目录名以 `_` 开头的包） | — |
| 登记一致性 | 新增包必须同时提交目录与 `catalog.json` 条目；反向（表里有、目录未落地）在 P0 迁移期允许——工具应**提示**而不是失败 | 否 |

`mobile.css` / `mobile.js` 必须可读：不得压缩（minify）、不得混淆、不得夹带与描述无关的第三方代码（见 §5「不得混淆」）。

## 3. 六项能力 → 对应断言

每张包只勾**真的做了**的能力，逐条在 390×844 / `(pointer: coarse)` 下用 Playwright 读**真实盒模型**断言。沿用 `移动适配模板/check-mobile.mjs` 的三层思路：**markup**（面板确实被识别）→ **styles**（能力数值成立）→ **scoping**（只影响目标面板）。

| 能力 | 判据 | CI 断言 | 适用面 |
|---|---|---|---|
| `hit-target` | 粗指针下面板内 `button / select / input` ≥ 44px | 面板容器内每个可点元素的最小边 `getBoundingClientRect()` ≥ 44（容差 0.5px）；不可见元素（`display:none` / `visibility:hidden` / 尺寸 0）跳过；`input` 另要求 `font-size` ≥ 16px 防 iOS 聚焦缩放 | 两个面都要 |
| `width-reclaim` | 面板根 `100vw` / 固定 px 不溢出 | 面板根 `rect.left ≥ -0.5` 且 `rect.right ≤ innerWidth + 0.5`；横向滚动容器（`overflow-x:auto`）自身宽度计入但不得把页面撑宽（`documentElement.scrollWidth ≤ innerWidth`） | 两个面都要 |
| `rail-clearance` | 面板让开折叠轨道（≤ 64px） | `mainContent`（或面板直接父级）计算后的 `padding-left` 落在 `[56, 64]`（0.8.0 包内样式：轨道 56px，文本比对、尚未在 0.8.0 真机实测）；同时断言面板左缘 ≥ 轨道宽 | 仅 `mobile-dedicated` |
| `chrome-collapse` | 按 `data-dsh-chrome="header"` 折叠顶栏 | 折叠前后面板内容区高度差 > 0，且折叠态 header 可见高度 ≤ 阈值（单行，约 44px）；展开可恢复 | 仅 `mobile-dedicated` |
| `notice-collapse` | `data-dsh-chrome="notice"` 折成一行且可展开 | 折叠态提示行数 = 1（`scrollHeight ≤ line-height × 1.5 + padding`）；点击可展开、再点可收起 | 仅 `mobile-dedicated` |
| `scroll-owner` | 面板状态主区可滚，不夺插件滚动 | 面板状态主区 `overflow-y` 为 `auto/scroll` 且内容可滚（`scrollHeight > clientHeight`）；滚到底后**插件自己的**滚动容器仍能滚动（没有被 `overscroll-behavior: contain` 之外的全局锁截断） | 两个面都要 |
| `floater-clearance` | 右下角浮动控件不再压住面板末尾内容 | 量出的 `--dshm-floaters` ≥ 控件高度；面板状态 `mainContent` 可滚；面板根 `margin-bottom` ≥ 控件高度；**滚到底后面板底部 ≤ 控件顶部**；opt-out 后归零 | 仅 `mobile-dedicated` |
| `shell-hit-target` | 外壳自身（返回栏 / 展开抽屉）的按钮 ≥ 44px | `.dshm-panelNav` 内每个 `button/[role=button]` 宽高 ≥ 44；抽屉 `[data-open="true"]` 内 `[data-slot="sidebar"]` 的按钮高度 ≥ 44；精指针下逐项零改动 | 仅 `mobile-dedicated` |

补充规则：

- **`scope` 决定断言组**：`catalog.json` 的 `scope` 为 `panel`（默认）或 `shell`。`shell` 类包（如 `shell-chrome`）只勾 `shell-hit-target`，`check-pack` 会跳过面板的三组断言而不是判它失败——但反过来也成立：声明了 `hit-target` 就必须真的把面板按到 44px。
- **opt-out 的落点随 scope 走**：`panel` 包认面板根或它的祖先；`shell` 包认文档根（`<html data-dsh-adapt="off">`），因为外壳没有「某个面板」这个边界。`check-pack` 的 fixture 把标记放在 `<html>` 上，两种包都必须因此完全回落。
- **未勾的能力不得出现对应选择器。** `check-pack` 从 CSS 里找特征选择器：出现 `[data-dsh-chrome=notice]` ⇒ 必须勾 `notice-collapse`；出现 `[data-dsh-chrome=header]` ⇒ 必须勾 `chrome-collapse`；出现推轨道的 `margin/padding-left: 56px` 类 ⇒ 必须勾 `rail-clearance`。
- **opt-out 断言**：给目标插件根加 `[data-dsh-adapt="off"]`（或文档化的面板级变量后）重跑一遍，六项断言中**至少本包勾选的项必须全部回落到基线**（例如按钮回到 28px），否则视为 opt-out 无效。
- **两个面**：`mobile-dedicated`（`window.__DSH_MOBILE_FRONTEND__ === 'dedicated'`，可用 `.dshm-*`）与 stock DSH web（≤720px，**不得碰 `.dshm-*`**，只做 `hit-target` 与 `width-reclaim`）。`surfaces` 登记了这个包声称覆盖的面，未登记的面不跑断言。
- **不使用 `:has()`**：兼容没有 `:has` 的 WebView；需要状态就用 `data-dsh-panel="1|0"` 这类 attribute。
- **不依赖 CSS Module 哈希**（`pI_x6G_` 这类前缀每次构建都会变），只用 `data-slot` / `[role=dialog]` / 已登记的 `.dshm-*` / 包自己写的标记。

## 4. `rail-clearance` 的显式偏离

0.8.0 在 ≤720px 上，抽屉收起后是 **56px 覆盖层**且**刻意不让位**（依据 0.8.0 包内样式与 0.7.1 实测；#306 只给 721–899px 补了 56px margin）。`core-panel` 在手机上推 56px 属于「与外壳意图不同」的一次显式偏离：

- 必须在包 README 里写明这条偏离与理由；
- `catalog.json` 必须 `default: "off"`（用户点名开启）；
- 只允许在 `mobile-dedicated` 面生效。

## 5. 审查规则

### 5.1 借 Greasy Fork 四条（原文语义）

| # | 规则 | 我们的落地检查 |
|---|---|---|
| 1 | **必须有描述** | `catalog.json` 的条目 + 包 README + `extension.json.description` 三者一致；说清目标插件、解决什么问题、怎么关。缺一项退回。 |
| 2 | **不得混淆 / 压缩** | `mobile.css` / `mobile.js` 必须格式化可读；不得 base64 包脚本、不得 `eval` 远程代码、不得夹带与描述无关的第三方代码。 |
| 3 | **不得超出描述范围** | 包只能做 `capabilities` 勾选的事、只能作用于 `target` 插件面板；发现「顺手改了全局风格 / 改了别的插件」即拒。 |
| 4 | **可删** | 维护者可移除任何包；包本身也必须「删目录即回滚」——不得要求改宿主、不得留下注册项、不得依赖一次性手工步骤。 |

### 5.2 我们加的两条

| # | 规则 | 落地检查 |
|---|---|---|
| 5 | **必须点名某个插件** | 包 README / 审查记录必须写明目标插件**包名 + 实测版本 + 至少一台真机**；禁止「适配所有插件」的匿名声明。唯一例外是 `core-panel`（`target: null` 的通配下限）：它必须列出实测过的插件清单，且 `default: "off"`。 |
| 6 | **必须 opt-out** | 目标插件根 `[data-dsh-adapt="off"]` 或文档化的面板级 CSS 变量；必须带实测证据（关掉后数值回落）。只有 `!important` 覆盖、没有 opt-out 的包不收。 |

补充：`risk: intrusive`（改结构 / 藏元素 / 动 `innerHTML`）一律 `default: "off"`；只有 `safe` + `stable` 才允许 `default: "on"`。

## 6. 风险等级 / 默认值 / 状态

```jsonc
"status": "stable | candidate | experimental | retired",  // 生命周期
"risk":   "safe | intrusive",                            // safe=纯 CSS 下限；intrusive=改结构/藏元素/动 DOM
"default": "on | off"                                    // on 仅限 safe + stable
```

- `experimental` → `candidate`（维护者过一眼、`check-pack` 全绿）→ `stable`（≥2 台真实设备验过）。
- `retired` 保留在表里但不再同步（上游收编 / 被替代 / 失效）。
- 宿主版本跨出 `runtime` 窗口时，包应被判「跳过」并在设置页提示，**不静默失效**。

## 7. `usesHostMarkers`：债务登记

`.dshm-*` 是 dsh-mobile 的内部类名，**没有公开契约**。包用到的每一个 `.dshm-*` 都必须登记进 `usesHostMarkers`；CI 对目标版本的 DOM 快照做存在性断言：

- 标记存在 ⇒ 通过；
- 标记消失 ⇒ 这张包**失败**（红在具体包、具体标记上），不是静默失效；
- 跨小版本（0.8.x）矩阵跑一次 DOM 快照，红了能定位到包。

stock 面不得使用 `.dshm-*`；用了就属于「未登记的私有标记」，直接拒。

## 9. 失败与退役

| 情况 | 处置 |
|---|---|
| 包在目标版本上断言失败 | 从 `on`/`candidate` 降级或标 `retired`；在 README 记录失败版本与原因 |
| 上游收编同一能力 | 标 `retired`，不再更新，保留索引指向上游 |
| 宿主标记消失 | CI 红到具体包 + 具体标记；包作者修选择器或退役 |
| 恶意 / 超出描述范围 | 直接移除，并在收录表留一条 `retired` 说明 |
